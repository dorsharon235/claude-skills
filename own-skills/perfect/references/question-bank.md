# Question bank — what usually needs knowing, per task type

A checklist, not a script. First take the needs of the skills you shortlisted (read their SKILL.md). Skip anything you can find in files or memory, and anything that would not change the result. Put recommended options first.

## Every task
- What is it for, and what counts as success? (one sentence the user would say)
- Language of the result (Hebrew / English / both).
- Who will see or use it?
- Where will it live (Instagram / YouTube / WhatsApp / a site / print / a meeting / internal)?
- What does the user already have (files, photos, logo, texts, an earlier version)?
- Must-haves and must-nots. An example of something he loves or hates.
- Deadline, and whether paid tools/credits are OK.

## Video
- Kind: cut from existing footage / animation from code / film with narrator / product promo / talking avatar / music clip.
- Length, and format (9:16 vertical, 16:9, 1:1).
- Story: opening hook, middle, ending (logo / call to action / date).
- Narration: none / his voice / a synthetic voice (which language, male or female, tone).
- Text on screen and captions (Hebrew? right-to-left).
- Music: style, energy, existing preference in memory; sound effects yes/no.
- Look: colours, fonts, brand, references ("like the video of...").
- Real people's faces: OK to show? privacy?

## Site / page / app screen
- Kind: landing page, full site, dashboard, form, tool.
- The one action a visitor should take.
- Content: who writes the texts, are there real images.
- Look: style references, brand colours, light/dark, Hebrew RTL.
- Where it is hosted, domain, does it need a login, data, payments.
- Phone first?
- Legal: personal data, accessibility (Israeli law), cookies.

## Deck / presentation
- Who is in the room, and what should they decide or feel at the end.
- Number of slides / minutes.
- Existing content, data, images; brand template.
- Format: Gamma / PowerPoint / PDF / an Artifact deck.
- Will it be presented live or sent to read alone (changes how much text).
- Language (Hebrew / English), name and logo.
- Investors / sales deck: amount raised and use of funds, product stage, team, business model and price, competitors. Market numbers: does he have them, or research them (cost?) — never invent.
- Screens or photos of the product to show; what is confidential.

## Document / report / letter
- Reader, and what he should do after reading.
- Tone (formal / friendly), length, language.
- Format (Word, PDF, Google Doc, email), letterhead.
- Sources and numbers to rely on; what is confidential.

## Game (Roblox or other)
- Age of players, core loop in one sentence, session length.
- Single / multi player, phone / PC.
- Look, references, existing place file.
- Money: game passes / none; safety for kids.

## Image / design / logo / 3D
- Use and size; transparent background?
- Style references, colours, must-include text.
- How many options to show.
- 3D print: printer, size, material, tolerances.

## Sound / music
- For what (video, game, app), length, mood, loop?
- Licence needs (commercial use?).

## Data / analysis / spreadsheet
- The question the data must answer.
- Source files and their location; what to do with missing values.
- Output: chart, table, dashboard, one number; who reads it.

## Code fix / feature
- What happens now vs what should happen; how to reproduce.
- Which project/folder; may I commit/push.
- How we will know it works (test, screen, real run).
